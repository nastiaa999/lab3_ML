# Лабораторная работа №3: сравнение LLM на задачах по ML

## Описание
Сравнение четырёх языковых моделей на 32 задачах по машинному обучению и классификации отказов оборудования (AI4I 2020).

## Модели
- GigaChat-2-Max
- Alice AI Flash
- gpt-oss-120b
- Qwen3-4B (локально, Ollama)

## Типы задач
| Тип | Описание | Проверка |
|-----|----------|----------|
| A | Расчётные задачи (Байес, деревья, метрики, SVM, наивный Байес) | Авто |
| B | Верно/неверно по теории ML | Авто + вручную (рубрика) |
| C | Выбор метода ML для сценария | Вручную (рубрика 0–2) |
| D | Написать код на sklearn | Вручную (запуск + метрика) |
| F | Изменённые версии A (другие числа), гипотеза H1 | Авто |
| E | LLM как классификатор отказов станка (few-shot) | Метрики F1 / balanced accuracy |

## Запуск
```bash
pip install -r requirements.txt
cp .env.example .env   # укажите API-ключи

# 1. Собрать банк задач
python make_bank.py

# 2. Прогнать банк и пилот через модели
python run_bank.py bank
python run_bank.py pilot

# 3. Подготовить тип E (разбиение AI4I + бейзлайны)
python prepare_e.py

# 4. Прогнать тип E
python run_e.py

# 5. Анализ результатов (ноутбук)
# 03_analysis.ipynb — таблицы, графики, гипотезы H1/H5/H12
```

## Структура
```
make_bank.py      # сбор банка задач (data/bank.csv, data/pilot.csv)
run_bank.py       # прогон банка через LLM -> results/*_answers.csv
prepare_e.py      # подготовка типа E (AI4I 2020)
run_e.py          # классификация отказов через LLM
03_analysis.py    # анализ: точность, гипотезы, цена, калибровка
check.py          # парсинг и оценка ответов
llm.py / prompts.py / tools/  # клиенты LLM, промпты, вспомогательные скрипты
data/             # банк, пилот, разбиение E
results/          # ответы моделей и итоговые таблицы
figures/          # графики анализа
review/           # бланки проверяющих
```

## Гипотезы
- **H1**: точность на учебниковых задачах A выше, чем на тех же с изменёнными числами F.
- **H5**: маленькая модель Qwen3-4B отстаёт больше в расчётах (A), чем в теории (B).
- **H12**: при 5 примерах few-shot LLM не хуже логистической регрессии, при 20 — проигрывает.

Результаты сохраняются в `results/tables/` и `figures/`.

## Результаты
Гипотеза H1 о запоминании учебниковых задач не подтвердилась: на задачах с изменёнными числами модели ошибались так же часто, как на исходных, а ошибки на учебниковых задачах были ошибками вычисления, а не памяти. Гипотеза H5 о размере модели опровергнута: маленькая Qwen3-4B решила все расчётные задачи и все ловушки, но отстала на теоретических утверждениях и выборе метода, где отказывалась отвечать или не приводила обоснования. Гипотеза H12 подтвердилась частично: при 5 примерах LLM не уступает логистической регрессии, но и при 20 примерах ещё не проигрывает ей.
Главный практический вывод ‒ уверенность модели ничего не говорит о правильности ответа. Все модели заявляли уверенность 96–98% при точности от 69% до 94%, а самые опасные ошибки (правдоподобие вместо вероятности, ошибка в сложении, выдуманное допущение при нехватке данных) сопровождались уверенностью 90–100%. Поэтому ответы LLM в задачах машинного обучения можно использовать как черновик и подсказку, но численные результаты нужно пересчитывать, код ‒ запускать и сверять с условием, а также читать рассуждение, а не только итоговую строку ответа.
